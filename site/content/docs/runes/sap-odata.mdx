# SAP OData Rune

```favnir
import rune "sap-odata"
```

SAP OData API（S/4HANA Cloud / Business One / ECC）を型安全に操作できる Rune。
BusinessPartner / SalesOrder / Material / JournalEntry の 4 エンティティと
購買（PurchaseOrder）をカバーする。

---

## fav.toml 設定

プロジェクトルートの `fav.toml` に `[sap]` セクションを追加する。
値には `${ENV_VAR}` 形式の環境変数参照を書ける。

```toml
[sap]
base_url = "${SAP_BASE_URL}"
username = "${SAP_USERNAME}"
client   = "${SAP_CLIENT}"
```

---

## 環境変数

| 変数名 | 説明 | 必須 |
|---|---|---|
| `SAP_BASE_URL` | SAP OData エンドポイント（例: `https://my.sap.example.com`） | ✓ |
| `SAP_USERNAME` | 認証ユーザー名 | ✓ |
| `SAP_PASSWORD` | 認証パスワード | ✓ |
| `SAP_CLIENT` | SAP クライアント番号（例: `100`） | |

## ctx.sap パターン

v90.1.0 以降、SAP へのアクセスは `AppCtx` 経由で行う（`ctx.sap.*` スタイル）。
設定取得を明示的に呼び出す必要はなく、`ctx` を受け取るだけでよい。

```favnir
fn sync_business_partners(ctx: AppCtx) -> Result<Int, String> {
    bind partners <- ctx.sap.business_partners(BusinessPartnerFilter {
        country:       Option.some("JP"),
        category:      Option.none(),
        changed_after: Option.some("2026-08-01"),
        top:           Option.some(500)
    })
    bind json <- Json.encode(partners)
    bind _    <- ctx.s3.put_object("favnir-sap-demo", "partners/latest.json", json)
    Result.ok(List.length(partners))
}
```

`SapClient` interface が提供するメソッド:

| メソッド | 説明 |
|---|---|
| `ctx.sap.business_partners(filter)` | 得意先・仕入先マスタ取得 |
| `ctx.sap.business_partner_by_id(id)` | 得意先 1 件取得 |
| `ctx.sap.sales_orders(filter)` | 受注データ取得 |
| `ctx.sap.materials(filter)` | 品目マスタ取得 |
| `ctx.sap.journal_entries(filter)` | 会計伝票取得 |
| `ctx.sap.batch(req)` | OData `$batch` による一括 CRUD |

## Ctx.build 自動設定注入

本番コードでは `Ctx.build()` を呼び出すだけで、`fav.toml [sap]` / 環境変数から
SAP 設定を自動読み込みして `AppCtx` を初期化する。

```favnir
bind ctx     <- Ctx.build()
bind partners <- ctx.sap.business_partners(BusinessPartnerFilter {
    country: Option.some("JP"),
    category: Option.none(),
    changed_after: Option.none(),
    top: Option.some(100)
})
```

`Ctx.build()` は `fav.toml [sap]` / 環境変数から SAP 設定を自動読み込みし、
`SapODataClient` を生成して `ctx.sap` に注入する。
パイプライン関数は設定の取得・管理を意識せず、`ctx` を受け取るだけでよい。

## QueryBuilder\<T\> Fluent API（v92.1.0〜）

`query<T>()` でビルダーを生成し、チェーン関数で OData クエリを型安全に組み立てる。
`use sap_odata.query_builder` でインポートする。

```favnir
import rune "sap-odata"

fn list_jp_partners(ctx: AppCtx) -> Result<List<BusinessPartner>, String> {
    bind q1 <- Result.ok(query<BusinessPartner>())
    bind q2 <- Result.ok(with_filter(q1, Eq("Country", "JP")))
    bind q3 <- Result.ok(with_select(q2, ["BusinessPartner", "BusinessPartnerName"]))
    bind q4 <- Result.ok(with_top(q3, 100))
    ctx.sap.business_partners_query(q4)
}
```

| 関数 | 説明 |
|---|---|
| `query<T>()` | 空の `QueryBuilder<T>` を生成 |
| `with_filter(q, expr)` | `FilterExpr<T>` を設定（`$filter`） |
| `with_select(q, fields)` | フィールドリストを設定（`$select`） |
| `with_expand(q, nav_props)` | ナビゲーションプロパティを設定（`$expand`） |
| `with_top(q, n)` | 取得件数上限を設定（`$top`） |
| `with_skip(q, n)` | スキップ件数を設定（`$skip`） |
| `with_order_by(q, field)` | ソートフィールドを設定（`$orderby`） |

> **E0018 注意**: `bind q <- ...` の再束縛は禁止。`q1` / `q2` / `q3` のように別名を使うこと。

## Page\<T\> によるページネーション（v92.4.0〜）

`Page<T>` はページ単位の取得結果を表す型。

```favnir
public type Page<T> = {
    items:     List<T>,
    next_link: Option<String>,
    total:     Option<Int>
}
```

| フィールド | 型 | 説明 |
|---|---|---|
| `items` | `List<T>` | 1 ページ分のエンティティリスト |
| `next_link` | `Option<String>` | 次ページの OData URL（最終ページは `none`） |
| `total` | `Option<Int>` | 総件数（`@odata.count`） |

`fetch_all_pages` で全ページを自動取得できる（v92.4.0 スタブ、v93.x 以降で完全実装予定）：

```favnir
public fn fetch_all_pages<T>(
    ctx:       AppCtx,
    builder:   QueryBuilder<T>,
    max_pages: Int,
    fetcher:   fn(AppCtx, QueryBuilder<T>) -> Result<Page<T>, String>
) -> Result<List<T>, String>
```

## W060 N+1 lint（v92.5.0〜）

`List.map` / `List.flat_map` コールバック内で `ctx.sap.*` を呼び出すと **W060** 警告が発生する。

```favnir
-- W060 検出対象（N+1 パターン）
bind results <- List.map(customer_ids, fn(id) {
    ctx.sap.sales_orders(SalesOrderFilter { sold_to: Option.some(id) })
})
```

推奨: `fetch_all_pages` または一括フィルタクエリを使う。

```favnir
-- 推奨（一括クエリ）
bind q1  <- Result.ok(query<SalesOrder>())
bind q2  <- Result.ok(with_filter(q1, Eq("SoldToParty", "CUST-001")))
bind all <- ctx.sap.sales_orders_query(q2)
```

## OData $batch による一括操作（v94.1.0〜）

`BatchRequest<T>` / `BatchOperation<T>` / `ctx.sap.batch` を使うと、複数の CRUD 操作を 1 回の HTTP リクエストで送信できる。

### BatchOperation\<T\> ADT

| バリアント | シグネチャ | 説明 |
|---|---|---|
| `BatchCreate(T)` | `BatchCreate(body: T)` | エンティティ新規作成 |
| `BatchUpdate(String, T)` | `BatchUpdate(key, body: T)` | 既存エンティティ更新 |
| `BatchDelete(String)` | `BatchDelete(key)` | エンティティ削除 |

### batch_request_builder\<T\> シグネチャ

```favnir
fn batch_request_builder<T>(entity_set: String, ops: List<BatchOperation<T>>) -> Result<BatchRequest<T>, String>
```

### 使用例

```favnir
import rune "sap-odata"

fn cleanup_partners(ctx: AppCtx) -> Result<String, String> {
    bind bps  <- ctx.sap.business_partners(BusinessPartnerFilter {
        country:       Option.some("JP"),
        category:      Option.none(),
        changed_after: Option.none(),
        top:           Option.some(200)
    })
    bind ops  <- List.map(bps, fn(bp) { BatchDelete(bp.partner_id) })
    bind req  <- batch_request_builder("A_BusinessPartner", ops)
    bind resp <- ctx.sap.batch(req)
    Result.ok(String.concat("deleted ", Int.to_string(List.length(resp.succeeded))))
}
```

`ctx.sap.batch(req)` は `BatchRequest<String>` を受け取り、`Result<BatchResponse<String>, String>` を返す。
`BatchDelete(key)` のようにキーのみの操作を使うと型パラメータが `String` に推論される。

## fav infer による型定義自動生成

`fav infer --from sap --metadata <url>` または `--metadata-file <path>` で
SAP の `$metadata` EDMX から Favnir 型定義を自動生成できます。

### EDM 型 → Favnir 型マッピング

| EDM 型 | Favnir 型 | 備考 |
|---|---|---|
| `Edm.String` | `String` | |
| `Edm.Int16` / `Edm.Int32` / `Edm.Int64` | `Int` | |
| `Edm.Decimal` / `Edm.Double` / `Edm.Single` | `Float` | |
| `Edm.Boolean` | `Bool` | |
| `Edm.DateTime` / `Edm.DateTimeOffset` | `String` | ISO 8601 形式 |
| `Edm.Guid` | `String` | UUID 文字列 |
| その他 | `String` | フォールバック |

### NavigationProperty → ExpandClause ヘルパー対応

`NavigationProperty` は `ExpandClause` ヘルパー関数として生成されます。

| NavigationProperty | 生成されるヘルパー関数 |
|---|---|
| `to_BusinessPartnerAddress` | `business_partner_expand_business_partner_address` |
| `to_Customer` | `business_partner_expand_customer` |
| `to_Supplier` | `business_partner_expand_supplier` |

詳細は [`fav infer` CLI ドキュメント](/docs/cli/infer) を参照してください。
